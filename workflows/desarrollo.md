# Workflow de desarrollo

## Equipo base

```
Architect → Engineer → Tester
                ↑         │
                └─────────┘
                 si falla
```

## 1. Architect

Recibe el problema y produce un plan.

## 2. Engineer

Recibe el plan y realiza la implementación.

## 3. Tester

Recibe la implementación y verifica los criterios.

## 4. Corrección

Si el Tester encuentra problemas:

1. El Engineer corrige.
2. El Tester vuelve a probar.
3. Se repite hasta cumplir los criterios.

## Regla principal

El equipo debe trabajar de forma incremental. Primero una versión mínima que funcione; después mejoras.
